日期：2026/10/04。原始 MVP 紀錄保留於下方。

- 後端：21 個測試通過，包含原 15 個測試及 6 個家庭整合測試；編譯零警告／零錯誤。
- 前端：10 個測試通過，TypeScript strict 與 Vite production build 成功。
- 發佈：Release 與 Debug publish 皆成功；Windows 應用程式控制在啟動 Release 時封鎖 Domain DLL（0x800711C7）。Debug 整合版正常啟動，以下瀏覽器驗收使用 Debug 後端與 production 前端。
- Docker 未於此輪實際建置或啟動。

## 後端家庭情境

| 情境 | 結果 |
| --- | --- |
| 個人、共同、待確認篩選 | 清單、月摘要、分類與趨勢金額一致；共同只計算一次 |
| 4 個相同 UUID 同時新增 | 只建立 1 筆；相同 UUID 不同內容回 409 |
| 同版本並行修改 | 1 個成功、1 個 409；保留建立者與歸屬，更新最後操作人 |
| 舊版本刪除／復原 | 回 409；不覆寫新資料 |
| 軟刪除與復原 | 排除已刪除金額，保留分類／帳戶參照，復原後金額回到統計 |
| 成員改名／停用 | 歷史名稱更新、保留關聯；停用者不得新增操作或新歸屬 |
| 舊版資料庫 Migration | 原始金額與備註保留，歸屬 Unknown、建立者空、版本 1 |

## 雙裝置瀏覽器驗收

使用 Edge headless 的兩個獨立 browser context，各有自己的 localStorage；使用獨立驗收資料庫，沒有向正式帳本加入示範交易。

- 兩裝置分別選操作人並新增個人交易；新增共同支出與收入後全家加總正確。
- 共同歸屬篩選只顯示共同金額。
- 同時打開一筆交易：第一位修改成功；第二位收到衝突提示，明確載入最新內容後可再修改。
- 回到前景刷新不覆寫表單內尚未儲存的金額。
- 詳細資料保留建立者，正確更新最後操作人。
- 取消刪除、確認刪除、跨月份已刪除清單及復原皆正常。
- 重開頁面，各裝置仍記住自己的操作人。
- 375×667、390×844、412×915、1200×900 的首頁、帳目、統計、設定與交易表單均無水平溢位；沒有瀏覽器未處理錯誤。

## 現有帳本升級

停止寫入時備份開發帳本後，啟動家庭版套用 Migration。比對全部原始欄位的 SHA-256 與筆數，升級前後一致；家庭欄位採未知歸屬、未記錄建立者，沒有加入測試帳目。備份存於工作區 .tools/backups，未納入 Git。

# MVP 驗收紀錄

日期：2026/10/03

環境：Windows、.NET SDK 8.0.425、ASP.NET Core 8.0.31、Node.js 24、Edge Chromium。

## 自動化測試

- `dotnet build --no-restore`：成功，零警告／零錯誤。
- `dotnet test --no-build`：15 個獨立測試全部通過。
- TypeScript strict 型別檢查與 Vite production build：成功。
- `vitest run`：4 個測試檔，7 個測試全部通過。
- `dotnet publish`：成功包含前端、Manifest、Icon 與 Service Worker。

後端測試包含新增收入／支出、金額零值／負數／超額小數拒絕、類型不符、遺失參照、空日期、交易修改與刪除、分頁驗證、分類與帳戶 CRUD、停用關聯保護、分類類型變更保護、ProblemDetails、一致小數加總、分類百分比、零交易月份、六個月趨勢及資料庫重新開啟後持久性。

前端測試包含金額與日期格式、切換收入分類、零金額拒絕、成功儲存、分類停用、連線錯誤及 API 驗證錯誤訊息。
